# ADR consistency review — 2026-11-18

This is a review of accepted ADRs 0001–0029. It documents reconciliations and remaining implementation risks; it is **not** an additional architecture decision.

## Conflicts resolved in this refactor

| Area | Earlier inconsistency / ambiguity | Resolution |
| --- | --- | --- |
| Archival readiness versus indexing | ADR-0014 and ADR-0019 required terminal indexing before archive publication | ADR-0027 requires a terminal crawl and validated WACZ, not Indexer availability; ADR-0014/0019 updated |
| Final archive status | ADR-0014 counted failed indexing as `COMPLETED_WITH_ERRORS` | Capture/preservation errors define archive outcome; indexing progress/failures are separate |
| Recording and packaging scope | ADR-0023 mixed formats, recorder integration, fidelity tests, replay, and publication | ADR-0023 narrowed to formats/replay interoperability; 0026 covers recording; 0027 covers publication |
| Authentication secrets in historical recordings | ADR-0015 stated sensitive headers must never appear in archived artifacts | Explicitly acknowledge that authentic WARC traffic can include credentials; protect, review, and control access instead of making an impossible absolute claim |
| Browser replica routing | ADR-0016 assumed Capture scaling without distinguishing interactive sessions | ADR-0028 defines a separate Capture-owned login manager process, while page workers scale independently |
| F5 scarce resource | ADR-0018 left domain resource unnamed | ADR-0021 defines global browser execution slots; F5 instructions now name the actual reservation invariant |
| Search product boundary | Search across all archives and search within one WACZ risked two app-level search implementations | ADR-0029 provides one OpenSearch-backed API with optional scope filters; ReplayWeb.page handles replay only |
| Provisioning | Older ADRs left Terraform optional | ADR-0024's Terraform-first choice now reflected in ADR-0004, 0008, and 0016 |
| Tooling text | ADR-0024 repeated the same OpenSearch smoke-test sentence | Duplicate removed |

## Deliberate ADR boundaries

- **0013 and 0025:** 0013 owns the distributed frontier and durable coordination; 0025 defines URL/navigation identity, scope policy, and minimum-depth correction.
- **0014, 0019, and 0027:** 0014 owns the SAGA and irreversible decision; 0019 owns the search indexing ledger and reconciliation; 0027 owns WACZ preparation and replay publication readiness. They should **not** be merged because their invariants and failure domains differ.
- **0015 and 0028:** 0015 owns authentication behavior and client choices after expiry; 0028 owns login execution, process deployment, and protected profile storage.
- **0022, 0023, and 0026:** 0022 owns fetch/discovery execution, 0023 the standards and interoperability, and 0026 the recording pipeline and fidelity acceptance gate. This separation removes overlapping recorder prescriptions.
- **0007, 0019, and 0029:** 0007 selects OpenSearch; 0019 describes asynchronous projection maintenance; 0029 defines one public search behavior.
- **0020 and 0021:** messaging reliability and resource concurrency are separate correctness concerns; no merge recommended.

There is currently no compelling benefit to renumbering or deleting historical accepted ADRs. Narrowing and cross-references preserve stable links and make each decision independently revisitable.

## Implementation questions that remain open

The following are not settled merely by accepting the high-level architecture:

1. **Recorder compatibility and archival fidelity:** prove a pywb/warcprox (or other existing recorder) integration with pinned Playwright/Chromium versions, authenticated HTTP traffic, WACZ assembly, and offline ReplayWeb.page playback. Browsertrix remains a reference and constrained fallback. This is the highest integration risk.
2. **MiniStack provider/data-plane fidelity:** verify DynamoDB transaction conditions, S3 byte ranges, OpenSearch indexing/search, and Terraform provider support using runnable smoke tests rather than emulator API creation alone.
3. **Auth-session delivery transport:** choose a supported backend browser-connectivity mechanism and verify short-lived authorized access. No UI/front-end technology or layout is chosen here.
4. **Contracts and state models:** define actual JSON Schemas, message catalog, RabbitMQ routing/retry topology, public HTTP paths and idempotency keys, DynamoDB tables/conditional expressions, outbox/inbox repair, WACZ manifest format, and search result contract. These should be written with the implementation, not guessed in conceptual ADRs.
5. **Artifact privacy:** choose and test a policy for sensitive HTTP requests/responses recorded in WARC, key management and encryption for auth profiles, and secure replay delivery. Generic promises to remove every credential from raw network records would be inaccurate.
6. **URL scope exceptions and hash routing:** ADR-0025 chooses a conservative same-origin default for navigational links, explicit resource rules, and a `#/...` / `#!/...` hash-route heuristic. Site-specific redirects, authentication origins, external assets, and alternative SPA routing require tests and opt-in rules.
7. **Publication visibility:** the system intentionally does not promise an instantaneous cross-service visibility flip. The actual API authorization and stale-event fencing mechanisms must satisfy the ADR-0014/0027 boundaries.

## Scope retained for later

No frontend architecture, UI composition, React/noVNC embedding design, or in-page search-highlight behavior is documented as decided. A backend endpoint for interactive browser access and a minimal self-hosted ReplayWeb.page delivery path are requirements; their presentation is deferred.

The architecture remains **four logical microservices** (Go Gateway, Go Coordinator, Python Capture, TypeScript Search/Index). The Capture-owned login manager is a separate process/deployment component, not a fifth independently owned business service.
