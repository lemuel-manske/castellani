# ADR implementation gaps

Status of the implementation against the accepted ADRs (29 ADRs, audited 2026-11-23).
Only observable gaps are listed; deferred-by-design items are noted where the ADR makes
them optional. Paths are relative to the repository root.

## 3. Implementation decisions without a compatible ADR

- **Identity generation:** Go uses `crypto/rand` hex with `run-`/`msg-`/`recovery-`/`lease-` prefixes; Capture uses UUIDv4 for attempts/snapshots and deterministic UUIDv5 keys for outbox IDs; Search uses `randomUUID`. ADR-0012 defines the envelope only, not identity generation. (`services/coordinator/adapters/persistence/dynamodb/api.go:66-89`, `services/capture/.../task.py:117-198`, `services/search/.../indexing-ledger.ts:51`)
- **Persistence schemas:** ADR-0005 defines ownership, not keys. All tables, GSIs, TTLs and `PAY_PER_REQUEST` billing are fixed in Terraform and duplicated in service adapters. (`infra/terraform/main.tf:2-300`)
- **Frontier keys:** `v1-` + SHA-256 of `url-v1:<normalized URL>`; the hash and version prefix are persisted identities, not covered by ADR-0025's normalization policy. (`services/capture/src/domain/url_identity.py:9,66-75`)
- **Capacity allocation:** numbered slot rows `0..9` scanned for the first unleased slot rather than a counter/increment; ADR-0021 leaves the algorithm open but does not record this choice. (`services/capture/src/adapters/persistence/dynamodb/alloc.py:71-115,156-174`)
- **Lease/retry timings:** 60s task/browser leases, 30s outbox lease with 0.5s poll and 5s retry, renewal at one-third of remaining time; Coordinator 30s reconciliation/2m stall/5 admission retries with 30ms backoff; Search 5 delivery + 5 indexing attempts with 120s leases. ADRs 0014/0020/0021 do not fix these values. (`services/capture/src/assembly/config.py:4-10`, `services/coordinator/config.go:24-26`, `services/search/src/assembly/config.ts:15-17`)
- **Health semantics:** readiness is a serve-state flag in Go, unconditionally true in Search, runtime-task state in Capture; Search has no liveness route. ADR-0016 requires health checks but not these semantics. (`services/coordinator/server.go:54-71`, `services/search/src/api/server.ts:29`, `services/capture/src/api/main.py`)
- **Search index:** one `archive-pages-v1` index, one shard, zero replicas, document ID = `snapshotId`, refresh-disabled writes. ADR-0029 explicitly defers mappings/ranking. (`services/search/src/adapters/search/topology.ts:1`, `opensearch.ts:7-59`)
- **Artifact staging:** `capture-staging/{archiveId}/{urlKey}/{attemptId}/{snapshotId}/...` in one versioned private bucket with SHA-256 verification; ADR-0006 defers naming and deduplication. (`services/capture/src/adapters/artifacts/s3.py:11,62-110`)
- **Idempotency retention:** 48h (ADR-0010 says "at least 24h") and 8–200 character keys with control-character rejection. (`services/coordinator/adapters/persistence/dynamodb/archive-queries.go:18,131-133`, `libs/httpx/validation.go:9-22`)
- **Internal layering:** Go uses `api/application/adapters/assembly`, Search adds an explicit `ports` layer, Capture has none; ADR-0008 defers internal layout. (`services/search/src/ports/search-index.ts`, `services/capture/src/assembly/runtime.py:30`)
- **Published-content visibility:** Gateway requires Coordinator `decision=PUBLISH`, `replay.status=READY` and a terminal published status before proxying archive metadata or WACZ; Capture rechecks the run's publication fields before serving the package object. ADR-0014/0027 require the visibility rule but not this transport-side enforcement. (`services/gateway/application/archive.go`, `services/capture/src/adapters/persistence/dynamodb/archive.py`)
- **Interactive session transport:** a dedicated internal `capture-login` manager serves `POST/GET/PUT /sessions`, a session-scoped browser UI, and an HTTP/WebSocket VNC proxy; Gateway routes session and browser traffic to it through `GATEWAY_CAPTURE_LOGIN_URL`. Live browsers are Playwright-managed headful Chromium under Xvfb with x11vnc/noVNC. Session metadata, idempotency keys, expiry/recovery and generation pointers use Capture-owned DynamoDB; `context.storage_state()` is AES-GCM encrypted with an application key before S3 storage. ADR-0015/0028 defer transport, UI and storage details. (`services/capture/src/login/`, `services/capture/src/application/login.py`, `services/gateway/api/session/browser.go`, `docker-compose.yaml`, `infra/terraform/main.tf`)
- **Archive retrieval transport:** `/archives/{id}/pages` uses a base64url DynamoDB cursor, and `/archives/{id}/wacz` serves `application/wacz` with single byte ranges, `If-Range` ETag validation and 400/416 problem responses. ADR-0027 fixes replay requirements but not these HTTP details. (`services/capture/src/api/metadata.py`, `services/capture/src/api/wacz.py`)

## 4. Priority

1. Close the end-to-end path: route/consume `StartCrawl` → crawl termination + manifest → WACZ packaging/publication → `ArchivePrepared`/`ArchivePublished` → SAGA completion (0012/0013/0014/0023/0027).
2. Consume stored authentication generations in page workers: detect auth rejection, block only affected tasks in `WAITING_FOR_AUTH`, support renewal/continue and fence stale workers (0015). The dedicated manager and protected profile storage already exist (0028).
3. Add fault injection, F1–F8 scenarios and metrics (0018); add the missing Search outbox and compensation events (0014/0020).
4. Resolve remaining contradictions in 0012, 0013, 0020, 0021/0018 and 0026.
